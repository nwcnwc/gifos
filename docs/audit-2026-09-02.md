# Security, stability and performance audit — 2026-09-02

Three passes over the tree at `8ba830b` (main): a catalog by eight parallel
readers, each on one surface; a second reading of every finding against the
code, with severities re-rated and each one decided as fixed here, deferred to
a maintainer decision, or recorded as an accepted residual; then the fixes,
each with its guard, on the branch `claude/fable-5-1-kr4fga`.

The surfaces: the app sandbox (SBX), the Cloudflare Workers (WRK), payments
(PAY), crypto and identity (CRY), the desktop and store (DSK), the parsers
(PRS), the mesh and meeting shell (MSH), and CI, scripts and supply chain
(OPS). Every finding that was fixed is described in the commit that fixed it;
this file is the index and the list of what is still open.

## What needs a person

In order of urgency. **Items 1-3 closed on 2026-09-03 by the v0.9.14 cut**
(`release/0.9.14` 7bfbd75c, build 2256): the release carries every fix
below plus the `.assets/` signature rules (a88792aa, 7bef82d5); the Workers
were deployed with it; the four apps were rebuilt and re-signed on the box
with the key (b2c3a2a8). What the cut's gate found is recorded at the end of
this section.

1. **Cut a release.** The Critical below (SBX-01) is fixed on the edge build
   only. Every frozen snapshot under `site/versions/` — including the one
   `version.json.current` sends a fresh visitor to — still has it, and
   snapshots are never edited. Until a release is cut from a freeze tag with
   these commits, pinned and default visitors run the old runtime.
2. **Deploy the Workers, before or with the site.** `./deploy-all.sh`
   (wrangler pinned) deploys relay, cors-proxy and mirror and sets the
   relay's `ABUSE_SALT` secret if it is missing (WRK-04). Order is not
   load-bearing — clients on the new `DS` land in sessions an old relay
   simply refuses (no device tag → 4012, verifier hashed differently), so a
   site deployed first is briefly unable to meet, and a relay deployed first
   serves old clients unchanged. `pay/` is in the script too now
   (`/transfer/bind`, claim-bound receipts, `TREASURY_ADDRESS`); the script
   refuses to run until its two required secrets are set by hand
   (`GIFOS_PAY_SIGN_JWK`, `PAYPAL_CLIENT_SECRET` — `pay/README.md`), and
   the site's broker expects the new Worker (`claim`, `/transfer/bind`).
3. **Rebuild and re-sign four apps.** beepbox, blockly-games, jupyterlite
   and svg-edit are ported off `prompt()` in their sources (svg-edit's five
   dialogs and beepbox's clipboard fallback ask through `gifosAsk`; Blockly's
   variable prompt is routed through `Blockly.dialog.setPrompt`; Pyodide is
   always handed a stdin), and `test/unit/app-modals.js` is green — but the
   listed GIFs under `site/apps/` are still the old bytes, deliberately: a
   rebuild invalidates their signature and the signing key is not on the box
   this ran on. On the box with the key:

       node apps/beepbox/build.mjs && node apps/blockly-games/build.mjs && node apps/jupyterlite/build.mjs && node apps/svg-edit/build.mjs
       GIFOS_SIGN_KEY=~/.gifos-signing-key-MAJOR-SECRET.json node scripts/sign-apps.mjs beepbox blockly-games jupyterlite svg-edit
       node scripts/build-app-catalog.mjs --check --require-signed

   The vendor builders (`vendor.mjs`) carry the same patches, so a moved pin
   reproduces them; beepbox's `EDITOR_SHA256` is the sha256 of the patched
   bundle.
4. **The flag day has been taken** (there are no users yet): CRY-01

## Deferred, with the reason

- **CRY-07** FINDLEAF/entry-PLACE carry no signer role; any seated member can
  author them. A mesh protocol change: `site/js/mesh.js` is a faithful port
  of `test/sim/mesh.cpp`, and the two must move together — not a change to
  make on one side.
- **MSH-10** bug-ledger §9/§10/§11 stay open as documented there; same
  reason.
- **PRS-07** the v1 (JSON + base64) decode is on the main thread, and an
  archive above V8's string limit can never open. A Worker does not lift the
  string limit; the remedy is the v2 archive (`GFA2`, file bytes as views),
  which the packer already writes. v1 remains readable for the GIFs that
  exist.
- **DSK-12** an edge computer takes a new worker over mid-session, and a
  page still running the old shell may lazily load a newer module. Edge is
  the channel that asked to track every push; the release channel is
  immutable and never does this. With one key per file the mix is at most
  "this session's modules plus the newest copy of one it had not loaded",
  and a reload resolves it.
- **OPS-14 (SHA pins)** see "What needs a person" 5.
