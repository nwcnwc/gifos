# SVG-Edit — gauntlet critic

Blind A/B against **SVG-Edit 7.4.2** (https://unpkg.com/svgedit@7.4.2/dist/editor/index.html — 85 tools, storage-consent dialog, shape library / star / polygon / connector / eyedropper on first paint) and **Boxy SVG** (https://boxy-svg.com/, the paid desktop bar the listing names). Distinct from **SVGOMG** (the optimiser already in this catalog — different job, different cover, different listing). Played ours from the packed GIF the way a stranger would: `/?run=svg-edit` → `run.html#id=…` in the real GifOS sandbox (`about:srcdoc`). Desktop 1280×800 and phone 390×844. One Chromium. Listing at `/store.html#app=svg-edit`. Icon frames from `site/apps/svg-edit/svg-edit.gif`. Invite was not two-tabbed.

**winner:** COMP

**single biggest remaining gap:** The left rail a stranger who knows SVG-Edit looks at first is missing. Comp 7.4.2’s first paint has shape library, star, polygon, connector, eyedropper under the image tool. This copy sets `noDefaultExtensions: true` because those files `import()` and the sandbox cannot fetch them, so the rail stops at image. Rect and ellipse draw; layers and source open; the SVG round-trips through `gifos.db('doc')`. That is an editor. It is not the editor they remember, and “as good as” the original is already losing. Inline those extensions the way the 274 toolbar images were inlined, or this stays a reduced SVG-Edit with a GIF around it. Boxy still wins node editing and a clean inspector.

**would a stranger who knows the original use this copy:** “I know SVG-Edit. The copy on unpkg opens: select, pencil, path, rect, ellipse, text, image, **shape library, star, eyedropper**, a paper, a storage prompt. This GIF opens on `about:srcdoc`, I drag a rectangle, I close it, the rectangle is still there, no consent dialog, no account. I would use this on a plane and to hand someone a file. I would still open unpkg or Boxy when I need a star, a library shape, or a path I can actually node-edit. The file-is-the-save / one-invite story is a reason I *would* switch — after the rail matches the one in my head.”

**HARD WALL:**

- **Catalog (held).** `site/apps/index.json` has 201 apps and **lists `svg-edit`**. Store search for “svg” returns **SVG-Edit, SVGOMG, Trianglify** as three different cards. `#app=svg-edit` listing loads. Signed by gifos.app. GIF 1.4 MB.
- **Overclaim (held for the editor; Invite unproven).** Listing copy describes a working editor, auto-save in the GIF, Open / Save SVG / PNG, “works on a plane,” and drops the extension suite on purpose. Those are true of this build: `#tool_rect` produced `<rect id="svg_1" … fill="#FF0000">`, `#tool_ellipse` produced `<ellipse id="svg_2">`, reload restored both from `gifos.db('doc')` (`rev` set, `len` 449, status “Saved on this device”). “Send Invite and everyone who opens the link draws on the same SVG” was not two-tabbed — last-write-wins on the whole SVG is documented, not demonstrated.
- **No CDN / no remote load (held).** App origin is the sandbox iframe. Manifest has no `network`. Zero off-origin requests from the app. Packed files are html/css/js + images map + COPYING + AUTHORS + help. The IIFE still contains a dead `cdnjs.cloudflare.com/ajax/libs/pdfobject` string and `import(\`${extPath}/…\`)` for extensions that are not loaded. Comp 7.4.2 fetches `ext-shapes`, `ext-connector`, `ext-grid`, `ext-opensave`, `ext-eyedropper`, `ext-polygon` from unpkg.
- **MIT inside the GIF (held).** `COPYING.txt` (MIT, SVG-edit authors 2009–2022), `COPYING-Apache-2.0.txt` (jGraduate), `AUTHORS.txt`, `help.md` decode from the GIF. Listing license line matches.
- **gifos.db / persist (held).** `doc` is read-write, `prefs` private. A rect+ellipse put in `drawing` survived reload onto `#svgcontent`. Open / Save SVG / PNG are three buttons on `#g-bar` that do not depend on `ext-opensave`. Save SVG and PNG both accepted a click (download path is `__gifosDownload`). Invite is OS chrome (`#appinvite` visible on the solo bar, labelled “Invite Friends join you live with one link”).

## Face (always judged)

- **Icon (64px):** 12 frames, 100 ms, a dark card holding a white artboard where a pen draws a star then a teal circle. The loop earns it — it demonstrates a vector drawing, it does not wiggle. At Home Screen size frame 0 is still a white rounded square with a tiny orange tick (reads “sticky note”); frame 6 is the star; frame 11 is star+circle+pen and *is* SVG-Edit. Comp has no animated icon. Structural win that now actually points at a working app.
- **Store art:** `screenshot.png` / `cover.jpg` is a photograph of the live window (red rectangle + selected ellipse, tools, rulers, palette, “Saved on this device”), GifOS shell cropped — the strip is the app’s own `#g-bar`. Mid-use, not empty first boot. At grid-card (search for “svg”) the red shapes still read; at listing hero they match the running window. Distinct from SVGOMG’s blue car on a chequer. Boxy’s marketing is a cleaner editor (selected path, fill panel). Ours now sells the app you get when you tap Install, not a poster of a crash.
- **Listing copy (read on `/store.html#app=svg-edit`):** Tagline *Draw SVG on this device — the file is the save, and one invite is a shared canvas.* Description leads with “not a whiteboard and not an optimiser,” then GIF-is-the-save, Invite, Open/export, unofficial MIT port, Boxy as the paid bar, and an honest “this copy drops the extra extension suite.” That is the right shape. Unofficial-port pill names SVG-Edit. Grid card is findable. Distinct from SVGOMG on the same search: editor vs optimiser, Creativity vs Utilities, 1.4 MB vs 497 KB.

## Product notes (not the gap, but they sit on the table)

- **COMP SVG-Edit 7.4.2** actually boots, and its left rail is longer. Storage consent on first load. Grey 2010 chrome, rulers, palette. Dated, and it is the full editor. Ours is the same IIFE with a dark coat and five tools ripped out. Homepage link is hidden (`#tool_editor_homepage` present, CSS `display:none`). Source dialog is still the original grey 2010 box (`se-svg-editor-dialog`) sitting on dark chrome — theme did not restyle it. It does open, and it shows the live SVG.
- **COMP Boxy SVG** is the feel bar: clean web-app chrome, path node editing, fill inspector, `LAUNCH APP`. Paid, account-shaped. The listing is right that travelling as a file is how we beat it, if the rail can draw what Boxy draws.
- **Phone 390×844.** Editor boots. `#tool_rect` draws a selected rectangle. `#g-bar` fits (Open / Save SVG / PNG + “Saved on this device”). 6 px horizontal overflow (`scrollWidth` 396 / `clientWidth` 390); the colour palette clips off the right. Selecting a shape wraps the 2010 property strip (id / class / x / y / w / h) over the top third of the paper. Help’s “tool strip is tight; rotate to landscape” is true, and it is not a fix. OS Invite/Save/Help eat the top; the app still fits under them.
- **Path / node tools** exist in the IIFE (`tool_path`, `tool_topath`, `tool_node_*`). Path mode engages (left rail highlights). A click sequence on `#svgcontent` left no `<path>` in this run (`#svgcontent`’s box reported 0×0, so the clicks never hit paper — not a product red, not a proof either). Rect/ellipse via drag on `#workarea` are the drawing that was actually proved.
- **Theme.** Dark CSS variables paint (`--main-bg-color: #16161e`). Workarea, `#g-bar`, and the chrome around the paper are dark. The editor’s own widgets (source dialog, layer list, many toolbar glyphs) are still 2010 grey-on-grey. It no longer looks like unpkg’s grey field. It does not look like Boxy.
- **Help.** Packed, ≥400 chars, describes drawing, Invite last-write-wins, phone. OS Help control is there.
- **404s on this box** were the desktop theme (`/themes/127/{theme,icons,wallpaper,eggs}.js`) and `changelog.json` — OS chrome, not the app.

The constructor wall is down. A rectangle lives in the GIF. Until the left rail is the one a stranger remembers from SVG-Edit — or clearly better — bar one still wins, and bar two is a reason they would switch *after*.
