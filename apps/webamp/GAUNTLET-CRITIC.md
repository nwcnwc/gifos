# Webamp — gauntlet critic

Blind A/B against Winamp 2.9 / https://webamp.org (Jordan Eldredge). Played the original in Chromium and this port from `apps/webamp/` (local server, gifos.db mocked). One browser. Desktop 1280 and phone 390 / 360. Listing read on `/store.html#app=webamp`. Icon frames read at 128px and at real Home Screen size (64px, next to the seeded 64px icons).

**winner:** COMP

**single biggest remaining gap:** First open is an empty Winamp. webamp.org is already a party: Llama Whippin' Intro in the marquee, 13 named tracks, a Milkdrop window, and a row of `.wsz` files on a Winamp 98 desktop. This copy opens onto `WINAMP 2.91`, a blank playlist, a flat EQ, and a dock that says "Room is live — playlist titles and EQ are shared" with nobody else there. Dropped files do land in the library and come back after reload. The EQ the listing promises does not: a 60 Hz band dragged to the top snapped back to 0 dB on reload, and `prefs` never received a write. The invite setlist never painted either — injecting a peer + mix + EQ left `#setlist` hidden and "Host playlist is empty." Bar two is the only way a port beats this original, and right now a stranger cannot see it.

**would a stranger who knows the original use this copy:** "I would use the GifOS one on a plane, or to hand someone the file with the songs inside — webamp.org is a tab that fetches `llama-2.91-*.mp3` and a skin museum. I will not, while the first screen is an empty player that claims a room is live, the EQ I just set is gone when I come back, and a friend joining the invite cannot see the setlist. That is not a reason to leave webamp.org. Put a playing window on first boot, keep the EQ in the file, show the shared playlist, then the offline + GIF reason is enough."

**HARD WALL:** catalog. `site/apps/webamp/{webamp.gif,cover.jpg,app.json}` exist (621 KB, signed). `site/apps/index.json` has no `webamp`. Store search for "webamp" is "Nothing matches that." The deep link still renders from `app.json`; the grid card a stranger browses does not. Runtime wall is clean: 16 requests, all same-origin, zero skin/CDN/unpkg/jsdelivr fetches. `connect-src` is not the issue. No `localStorage` in the app. `COPYING-webamp.txt` rides in the tree. Listing claims that were checked: unofficial, Jordan Eldredge, MIT, no llama MP3 shipped. EQ-persist and "a friend sees the same playlist" are overclaims of this build — a failed round, not a sandbox break.

## Face (always judged)

- **Icon (64px):** A grey Winamp main window, vis bars bouncing, time ticking `1:20`→`1:21`, play button lit, seek head moving. The loop demonstrates, it does not wiggle. At real Home Screen size (seeded icons are 64×64) it still reads "player" — WINAMP title is a speck, the green vis and transport row are what land. Original has no animated icon, so this is a small structural win that does not yet earn the slot next to Welcome.gif / Camera.gif.
- **Store art:** `screenshot.png` / `cover.jpg` is a pixel mockup (1200×720, no shell toolbar): block-letter WINAMP, PREV/PLAY/PAUSE, a fake 8-song playlist ("AFTER HOURS - SODIUM LIGHT"). It matches neither webamp.org's real 2.91 chrome nor this port's running window (which *is* that chrome). Beside the catalog's best covers (2048, Flexbox Froggy, JS Paint — all the actual product mid-use) it looks like a different, cheaper gadget. Hero on `/store.html#app=webamp` and the phone listing both show this fake. A shopper who knows webamp.org would not recognise the product. Retake from the real `#main-window` + EQ + playlist with tracks in it.
- **Listing copy (read on the rendered store page):** Tagline *Winamp 2.9 that lives in a GIF — playlist, EQ, and your MP3s stay in the file, even on a plane.* Description leads with file-is-the-save and Invite, then the three windows, then unofficial. That is the right shape, and it is better store copy than webamp.org's "Winamp 2 in your browser." Two claims are not true of the build it ships beside: the EQ does not stay in the file (reload restored tracks from `library`, not `prefs.ser`; the 60 Hz band reset), and a friend does not see the playlist (setlist stayed hidden). "The base skin is inside the file, so it looks like Winamp the first time you open it" is true of the chrome and false of the cover.

## Product notes (not the gap, but they sit on the table)

- The three windows *are* Winamp 2.91. Main 275×116, EQ 275×116, playlist 300×406 on desktop, stacked 275-wide on a 390 phone. Title bar, vis, marquee, volume/balance, EQ graph, presets, ADD/REM/SEL/MISC — same engine as the original. Blind on the chrome alone this is a tie, not a win. Milkdrop is off (`milkdropEnabled:!1`); authentic 2.9, and a reason the original still looks more alive.
- Dropped audio works. `+ MP3s` → two WAVs (same File/Blob path as MP3) wrote 88244-byte rows in `library` and the playlist named them. Hint: "2 added — saved in this file." Reload restored both tracks from those bytes. Playlist *order* did not (night-drive was first; sodium-light came back first) because `prefs.list` never wrote.
- EQ works as a control (60 Hz handle and the red graph moved). It is not saved. `handleAddUrlEvent` refuses fetch. Skin button is there; no `.wsz` was dropped this round. Default skin is the compiled CSS — no CDN.
- Phone stack (main / EQ / playlist, `body.phone.scroll`, dock with + MP3s) is usable and better than an unstacked 2.9 layout on 360. The buttons are still 2.9 pixels; a finger wants the dock, not shade/close. Hint truncates.
- Invite / gifos.db are in the code (`net.js` mix+eq rows, `library` private). Not two-tabbed here (one Chromium). The solo hint always treating the owner's own peer row as "others > 0" is why first boot lies about a room. `paintSetlist(mix, null)` from `onMix` hides the list it just received.
- No demo track. That is a choice (no llama, no CDN) and it is the first thing a stranger sees. The cover invents songs the file does not contain.

The run is not done. Greet with a playing window that is this skin, keep the EQ in `prefs`, paint the shared setlist, retake the cover from that real window. Until a stranger looks at first boot and says "that's Winamp, and the file is why I'm here," bar two does not matter.
