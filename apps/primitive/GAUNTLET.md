The photo and the triangles live in the file, so you can close it on a plane and the reconstruction is still there — the original demo forgets everything the moment you leave the tab.

Choose a picture and Take photo persist the original as a `data:image/` in the file, never a `blob:` URL. Close and reopen is the same picture plus the last triangles — Try a sample is no longer the only path that restores.

Distinct from Pixel It: triangles one at a time, not a pixel-block palette snap.

## Bars

- **ONE:** [primitive.js](https://ondras.github.io/primitive.js/) / [primitive.lol](https://primitive.lol) — redraw a photo by adding triangles.
- **TWO:** offline; source photo + reconstruction saved in the GIF; take-photo clip; Stop; Quick/Classic/Fine; hold-to-compare.

## Rounds

1. Vendor the algorithm (no URL fetch, no workers). GifOS chrome: empty state, Start/Stop, presets, shape chips, raster/vector, PNG/SVG download.
2. Persist original + reconstruction + settings in the file; restore without re-running (the original is stochastic, so a re-run is a different picture). Chosen / camera photos now survive close: bytes go in as a data URL, a dead `blob:` is refused on restore.
3. Icon: a face emerging from triangles, readable at 64px.
4. Cover: mid-reconstruction portrait, not an empty first boot.
5. Listing leads with the file-is-the-save, not a feature list.

## Remaining gap

Cover is still a pixel-font mock of chrome the running app does not use, not a real photograph mid-reconstruction. Quick (20 shapes) is a smear, not that mask. Fine is minutes on a phone — same as the original; we do not pretend otherwise. Comp keeps original and result side by side; we hold-to-peek.
